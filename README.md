Homework 27 "Опціональні та readonly-властивості, union та літеральні типи, псевдоніми типів, інтерфейси"

Що робите:
Ви типізуєте сервіс сповіщень - модуль, який приймає заявку на відправку сповіщення, валідує її і віддає результат.

Пишіть на чистому TypeScript, без Express, без бази, без запитів по мережі. Усе, що «зовнішнє», ми імітуємо звичайними функціями. Вам потрібно описати систему типів, у якій неможливо зробити помилку.

Правила
strict: true у tsconfig.json. Обов'язково.
Жодного any (я вам буду про це нагадувати)Ніде. Якщо здається, що без нього не обійтись - це саме те місце, де ваше дз може стати цікавішим. Використовуйте unknown.
Жодного as (крім as const). Каст - це обіцянка компілятору, а не перевірка. Завдання побудоване так, щоб касти не знадобились.
Проєкт має компілюватись: npx tsc --noEmit без помилок.
Ніяких зовнішніх бібліотек. zod та інші валідатори тут не потрібні.

Завдання 1 — Модель користувача
У файлі domain.ts опишіть інтерфейс User:

Завдання 4 - Дискриміноване об'єднання
Файл payload.ts

Опишіть тип NotificationPayload - об'єднання трьох варіантів із різними наборами полів:

Варіант - Email, Дискримінатор - channel: "email" , Свої поля -  to: string, subject: string, body: string, attachments? — масив рядків
Варіант - SMS, Дискримінатор - channel: "sms", Свої поля - to: string, text: string (не body!)
Варіант - Push, Дискримінатор - channel: "push"	, Свої поля - deviceToken: string, title: string, body: string, badge?: number
Вимоги:

Спільне поле для всіх трьох - priority з літеральним union "low" | "normal" | "high".
Напишіть функцію describe(payload: NotificationPayload): string, яка через switch по channel повертає різний опис для кожного каналу
Усередині кожної гілки switch зверніться до полів, специфічних для цього каналу
Нижче закоментованим кодом покажіть: у гілці "sms" звернення до payload.subject - помилка компіляції. Це і є та сама гарантія, заради якої весь паттерн існує.
